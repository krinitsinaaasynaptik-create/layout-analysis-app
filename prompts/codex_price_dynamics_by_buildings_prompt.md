# Задача для Codex: автоматизировать отчет “Динамика цен по застройщикам и домам”

## Контекст

В сервис аналитики предложений застройщиков нужно добавить второй отчет, который раньше собирался вручную.

Этот отчет отличается от сводного отчета по площадям. Здесь важна не только общая сводка по рынку, а **детальная аналитика по каждому застройщику и каждому дому / корпусу / проекту**.

Главная задача отчета — показывать, как менялась цена за м² во времени:

- по застройщикам;
- по проектам;
- по домам / корпусам;
- по площадям квартир;
- по периодам;
- по каждому историческому срезу данных;
- с фиксацией роста, снижения, появления и исчезновения предложения.

Важно: отчет не должен быть жестко привязан только к месяцам. Если выгрузка данных будет делаться чаще, пользователь должен видеть динамику за меньший промежуток: по срезам, дням, неделям или месяцам.

# 1. Название и размещение отчета

Добавить отчет в раздел:

```text
Дашборд
```

Название внутренней страницы:

```text
Динамика цен по домам
```

Рекомендуемый URL:

```text
/dashboard/price-dynamics
```

или:

```text
/reports/price-dynamics
```

В навигации внутри `Дашборд` должно быть две страницы:

```text
Сводный отчет по площадям
Динамика цен по домам
```

Если внутренней навигации раздела `Дашборд` еще нет, добавить вкладки:

```text
[Сводный отчет по площадям] [Динамика цен по домам]
```

---

# 2. Цель отчета

Отчет должен отвечать на вопросы:

```text
Как менялась цена за м² у каждого застройщика?
```

```text
Как менялась цена за м² по каждому дому / корпусу?
```

```text
Где цена растет, снижается или остается стабильной?
```

```text
В каких домах появились новые предложения?
```

```text
Какие позиции ушли из экспозиции?
```

```text
Как КССК выглядит относительно конкурентов по динамике цены?
```

---

# 3. Источник данных

Отчет должен строиться из текущих данных сервиса, а не из отдельного файла.

Использовать существующие сущности:

```text
Developer
Project
Building
Apartment
Snapshot
ApartmentSnapshot
LayoutGroup
```

Главный источник для динамики:

```text
Snapshot
ApartmentSnapshot
```

Важно: отчет должен строиться по историческим срезам. Если история не сохранена, нужно доработать механизм сохранения так, чтобы при каждом обновлении данных создавался новый срез.

---

# 4. Главное требование: сохранять историю

Отчет невозможен без истории.

При каждом обновлении данных нужно сохранять отдельный срез.

## 4.1. Snapshot

Сохранять:

```text
snapshot_id
snapshot_date
source
developer_id
status
created_at
```

## 4.2. ApartmentSnapshot

Сохранять:

```text
snapshot_id
apartment_id
developer_id
project_id
building_id
rooms
area
floor
price
price_per_sqm
status
layout_group_id
created_at
```

Важно:

- старые срезы не удалять;
- старые цены не перезаписывать;
- каждое обновление должно создавать новый исторический срез;
- если квартира исчезла из текущего среза, не удалять ее физически;
- если квартира была раньше, но отсутствует сейчас, помечать ее как `gone_from_exposure`.

Не считать исчезновение продажей без явного статуса продажи.

Использовать формулировку:

```text
ушла из экспозиции
```

# 5. Логика периодов и детализации динамики

Отчет должен строиться по историческим срезам данных.

Главное правило: каждое обновление данных должно сохраняться как отдельный срез, и отчет должен уметь показывать динамику между срезами.

Не ограничивать отчет только месячной динамикой.

---

## 5.1. Режимы детализации

Добавить переключатель детализации:

```text
По срезам
По дням
По неделям
По месяцам
```

Главный режим для точной динамики:

```text
По срезам
```

По умолчанию можно использовать:

```text
По срезам
```

Если данных слишком много, можно по умолчанию показывать:

```text
По неделям
```

Но архитектура должна поддерживать все четыре режима.

---

## 5.2. Режим “По срезам”

В этом режиме каждая колонка или точка графика — это отдельное обновление данных.

Пример колонок:

```text
17.04.2026
25.04.2026
03.05.2026
17.05.2026
```

Если в один день было несколько обновлений, показывать дату и время:

```text
17.05.2026 10:30
17.05.2026 18:45
```

Этот режим нужен, если выгрузки будут делаться чаще, чем раз в месяц.

---

## 5.3. Режим “По дням”

Для каждого дня использовать последний доступный срез внутри дня.

Важно: не суммировать все срезы дня между собой, иначе квартиры будут задвоены.

Если в дне нет среза, день можно пропустить или показать как `нет данных`.

---

## 5.4. Режим “По неделям”

Для каждой недели использовать последний доступный срез внутри недели.

Неделю отображать как период:

```text
06.05–12.05
13.05–19.05
20.05–26.05
```

Не суммировать срезы недели между собой.

---

## 5.5. Режим “По месяцам”

Для каждого месяца использовать последний доступный срез внутри месяца.

Месяц отображать как:

```text
Апрель 2026
Май 2026
Июнь 2026
```

Не суммировать срезы месяца между собой.

---

## 5.6. Сравнение с предыдущим периодом

Для каждой группы сравнивать текущий период с предыдущим доступным периодом выбранной детализации.

Группа:

```text
developer + project + building + area_group
```

Основной показатель:

```text
median_price_per_sqm
```

Формулы:

```ts
change_abs = current_median_price_per_sqm - previous_median_price_per_sqm

change_pct =
  previous_median_price_per_sqm > 0
    ? ((current_median_price_per_sqm - previous_median_price_per_sqm) / previous_median_price_per_sqm) * 100
    : null
```

Если группа есть в текущем периоде, но ее не было в предыдущем:

```text
новое
```

Если группа была в предыдущем периоде, но отсутствует в текущем:

```text
ушло
```

---

## 5.7. Фильтр периода

Добавить фильтр периода:

```text
Последние 7 дней
Последние 30 дней
Последние 90 дней
Последние 6 месяцев
Последние 12 месяцев
Все время
Произвольный период
```

По умолчанию:

```text
Последние 90 дней
```

Если данных меньше, показывать доступный период.

---

## 5.8. Поведение графиков

Графики должны перестраиваться в зависимости от выбранной детализации:

- `По срезам` — точки соответствуют конкретным срезам;
- `По дням` — точки соответствуют последнему срезу каждого дня;
- `По неделям` — точки соответствуют последнему срезу каждой недели;
- `По месяцам` — точки соответствуют последнему срезу каждого месяца.

---

## 5.9. Empty states для детализации

Если есть только один срез:

```text
Недостаточно истории для расчета динамики. Динамика появится после следующего обновления данных.
```

Если нет срезов за выбранный период:

```text
Нет данных за выбранный период.
```

Если выбран режим `По дням`, `По неделям` или `По месяцам`, но в периоде есть только один агрегированный период:

```text
Недостаточно периодов для расчета изменений. Попробуйте выбрать режим “По срезам” или расширить период.
```

# 6. Уровни детализации отчета

Отчет должен работать на нескольких уровнях.

---

## 6.1. Застройщик

Показывать динамику по каждому застройщику.

Ожидаемые участники рынка могут включать:

```text
КССК
Железно
КСМ
Маяковская
УКС Авитек
СМУ5
СтройСоюз
КИНО девелопмент
ПрофСтрой
Алтай-Строй
Сретенский посад
ПС Недвижимость
```

Список нельзя хардкодить. Он должен строиться динамически по данным в базе.

---

## 6.2. Проект

Внутри застройщика показывать проекты:

```text
Застройщик → Проект
```

---

## 6.3. Дом / корпус

Внутри проекта показывать дома / корпуса:

```text
Застройщик → Проект → Дом
```

Если в данных нет отдельного дома, использовать проект как уровень дома.

---

## 6.4. Площадь / диапазон площади

Внутри дома нужно показывать строки по площадям квартир.

Если в данных есть точная площадь, группировать по точной площади или близкому диапазону.

Примеры:

```text
31 м²
44–45 м²
73,8–76,9 м²
```

Если площади немного отличаются, можно группировать в диапазон с округлением.

Рекомендуемая MVP-логика группировки:

```text
если площади отличаются не более чем на 1 м², объединять в диапазон
```

Например:

```text
44.1, 44.6, 45.0 → 44–45 м²
```

Если площадь одна:

```text
31 м²
```

# 7. Что считать в отчете

Главный показатель:

```text
Цена за м²
```

Для каждого периода, застройщика, проекта, дома и площади считать:

```text
min_price_per_sqm
max_price_per_sqm
median_price_per_sqm
avg_price_per_sqm
apartments_count
```

Основным отображаемым показателем сделать:

```text
median_price_per_sqm
```

Если в группе несколько квартир с разной ценой за м², показывать диапазон:

```text
min_price_per_sqm – max_price_per_sqm
```

Если цена одна, показывать одно значение:

```text
125 000
```

Если значение изменилось относительно предыдущего периода, показывать изменение:

```text
125 000 (+5 000)
```

или:

```text
125 000 (-3 000)
```

# 8. Основная таблица отчета

Нужна таблица, где строки — это структура:

```text
Застройщик
  Проект
    Дом
      Площадь / диапазон площади
```

Колонки — периоды выбранной детализации.

Пример для режима по месяцам:

| Застройщик / проект / дом / площадь | Февраль 2026 | Март 2026 | Апрель 2026 | Май 2026 | Изм. к пред. периоду |
|---|---:|---:|---:|---:|---:|
| Железно |  |  |  |  |  |
| → ZNAK |  |  |  |  |  |
| → Дом 17 |  |  |  |  |  |
| → 44–45 м² | 123 000 | 125 000 (+2 000) | 125 000 | 128 000 (+3 000) | +3 000 |
| → 31 м² | 119 000 | 119 000 | — | — | ушло |
| КСМ |  |  |  |  |  |
| → Михеева, 17 |  |  |  |  |  |
| → 39,8 м² | 98 200 | 99 200 (+1 000) | 99 928 (+728) | 101 900 (+1 972) | +1 972 |

Требования:

- строки застройщика должны быть визуально выделены;
- строки проекта / дома должны быть вложенными;
- строки площади должны содержать значения;
- пустые значения показывать как `—`;
- если предложение исчезло, показывать `ушло из экспозиции` или коротко `ушло`;
- если предложение появилось впервые, показывать `новое`;
- если цена изменилась, показывать абсолютное изменение в скобках;
- таблица может быть широкой, поэтому нужен горизонтальный скролл;
- первая колонка с названием группы должна быть sticky, если это несложно.

# 10. Расчет изменения цены

Для каждой группы:

```text
developer + project + building + area_group
```

Сравнивать текущий период с предыдущим доступным периодом.

Основной показатель для сравнения:

```text
median_price_per_sqm
```

Формулы:

```ts
change_abs = current_median_price_per_sqm - previous_median_price_per_sqm
change_pct = ((current_median_price_per_sqm - previous_median_price_per_sqm) / previous_median_price_per_sqm) * 100
```

Если предыдущего периода нет:

```text
новое
```

Если в предыдущем периоде значение было, а в текущем нет:

```text
ушло
```

Если предыдущее значение равно 0 или отсутствует, процент изменения не считать.

# 20. Форматирование

Цена за м²:

```text
125 000 ₽/м²
```

Изменение:

```text
+3 000 ₽/м²
-2 000 ₽/м²
```

Проценты:

```text
+2.4%
-1.1%
```

Площадь:

```text
44–45 м²
31 м²
73,8–76,9 м²
```

Период:

```text
17.05.2026
17.05.2026 10:30
06.05–12.05
Май 2026
```

1. Добавлена страница `Динамика цен по домам`.

6. Есть детализация по проекту.

10. Есть режим `По дням`.
11. Есть режим `По неделям`.
12. Есть режим `По месяцам`.
13. Основная таблица показывает цену за м² по выбранным периодам.
14. Значения показывают рост / снижение к предыдущему периоду.
15. Есть сводка по застройщикам.
16. Есть сводка по домам.
17. Есть блок КССК vs конкуренты.
18. Есть ключевые выводы.
19. Есть графики.
20. Есть фильтры.
21. Есть экспорт.
22. Есть empty states.
23. Основные расчеты покрыты тестами.
